# はじめて設計する REST API

会議室の椅子が壊れました。社員は修理を頼み、総務は未完了の依頼を探し、修理が終わったら状態を更新します。二つの画面から同じ依頼を扱うには、どんな約束が必要でしょうか。この教材では、依頼を1件ずつ追いながら、その約束を HTTP API として設計します。

**[第1章「API とは何か」から読む](docs/01-api.md)**。第1〜6章は、プログラムを書いた経験がなくても読めます。実際に動かしたい方は、[第7章のローカル実習](docs/07-fastapi.md)から始められます。手元の実習に AWS アカウントは不要です。

## サンプルの構成

| 場所 | 内容 |
| --- | --- |
| [package/app](package/app) | FastAPI による入力の検証、受付、修理依頼の読み書き |
| [package/db](package/db) | Alembic によるテーブルの作成と変更履歴 |
| [package/infra](package/infra) | API Gateway、Lambda、Aurora PostgreSQL を配置する Python CDK |
| [tests](tests) | 利用者が受け取る HTTP 応答を確かめるテスト |

HTTP の意味は RFC、REST の成り立ちは提唱者の原典に沿って説明します。複数形のパスや受付件数の上限など、設計者に委ねられた部分は、採用した理由を例に添えています。各章の本文から該当する仕様の節や公式の技術資料を確認できます。
