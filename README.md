# はじめて設計する REST API

椅子の修理をスマートフォンから頼んだ社員が、翌日、受付番号で進み具合を確かめます。画面は何を送り、受付は何を返せばよいでしょうか。この教材では、1件の修理依頼が登録されてから完了するまでをたどり、その取り決めを OpenAPI の仕様書にします。

## 対象と読み方

対象は、初めて Web API を設計する人です。設計編はプログラミングや AWS の経験がなくても読めます。通信に使う JSON と、仕様書を書く YAML は例の中で紹介します。実装も試す人は、Python 3.12 と uv を使います。AWS への配置には AWS アカウントとデプロイ権限が必要です。

| 目的 | 読む順序 | 読み終えたときにできること |
| --- | --- | --- |
| 初めて設計する | 第1〜7章 → 第8章の会議室予約 → 第11章の互換性判断 | 業務から対象を選び、メソッド・パス・入力・成功と失敗のレスポンスを決め、仕様書にする |
| 自分の案件に当てはめる | [空欄の設計シート](docs/templates/contract-sheet.md) をコピー → 第6章と第8章の記入例 | 一つの操作について「誰が何を送ると、何が起きるか」を説明し、確認条件を決める |
| コードを動かす | 第9章で API を起動 → 第4章の curl → 第10章で AWS の構成を確認 | 手元で登録と照会を試し、同じ操作が AWS でどこを通るかを追う |

初めての用語は [用語集](docs/glossary.md) からも引けます。

## サンプルで試せること

教材の **サンプルで試せる** は、このリポジトリのコードで確かめられる例です。次の5操作を実装しています。受付番号には登録レスポンスの `id` が入ります。

| 操作 | リクエスト | 成功時に確かめること |
| --- | --- | --- |
| 修理を依頼する | `POST /repair-requests` | `201`、受付番号、依頼を開くための `Location` |
| 依頼を探す | `GET /repair-requests?status=open&limit=10` | `200` と一覧。続きがあれば `next_after` |
| 1件を開く | `GET /repair-requests/{request_id}` | `200` とその依頼の件名・場所・状態 |
| 完了にする | `PATCH /repair-requests/{request_id}` | `200` と変更後の依頼 |
| 誤登録を取り除く | `DELETE /repair-requests/{request_id}` | `204`、本文なし。その番号を再び開くと `404` |

**設計例（未実装）** は、業務の条件が変わったときの選択肢です。ログインや `/me`、本人だけが変更できる権限、`ETag` と `If-Match`、二重登録を防ぐキー、入力欄の位置を示す `errors[].pointer`、会議室予約はこちらに含まれます。サンプルは利用を許可した人が同じ台帳を扱う構成です。
