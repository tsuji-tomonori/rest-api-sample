# はじめて設計する REST API

「修理を依頼した社員に、その場で受付番号を返したい」。この一文から、どんな API を設計すればよいでしょうか。受付番号で何を識別するか、同じ登録が2回届いたらどうなるか、入力に誤りがあれば何を返すか。画面を作る人が迷わず使えるように、こうした約束を一つずつ決めます。

初めての方は **[第1章「API とは何か」](docs/01-api.md)** から読んでください。自分の業務の API を設計する方は **[第6章の設計シート](docs/06-contract.md)** を開き、判断に迷う欄から各章へ戻れます。第7章までで、その設計を OpenAPI 形式の仕様書にまとめます。

| 章 | この章で答える問い |
| --- | --- |
| [1　API とファイル連携](docs/01-api.md) | 誰が、いつ、どの単位で結果を必要とするか |
| [2　REST とリソース](docs/02-rest.md) | 利用者は何を一つの対象として扱い、どんな状態を見るのか |
| [3　パスとパラメータ](docs/03-addresses.md) | パスをどこで区切るか。注文番号、検索条件、パスワード、認証トークンはそれぞれどこに置くか |
| [4　HTTP メソッドと要求の書き方](docs/04-methods.md) | 注文を見るときはなぜ GET、ログインするときはなぜ POST か。論理削除にも DELETE を使えるか |
| [5　応答とステータスコード](docs/05-responses.md) | 2xx・4xx・5xx をどう選ぶか。入力の誤り、業務上の競合、サーバーや中継の障害をどう伝えるか |
| [6　設計を一つの契約にまとめる](docs/06-contract.md) | 一覧・詳細・登録・変更・削除で、宛先、本文、応答がどう変わるか。自分の業務の契約にどう落とし込むか |
| [7　OpenAPI で仕様を書く](docs/07-openapi.md) | パス、入力、応答をどう記述し、実装から同じ形式で出力するか |
| [8　FastAPI による実装例](docs/08-fastapi.md) | 設計した一つの操作が Python のどの記述に対応するか |
| [9　AWS での構成例](docs/09-aws.md) | API Gateway、Lambda、Aurora の間を何の設定でつなぐか |
| [10　会議室予約の設計例](docs/10-practice.md) | 二重予約をどう防ぐか。登録や通知が途中で止まったとき、どこまで取り消し、どこから再開するか |

HTTP メソッドや応答コードの意味は、本文から RFC の該当節で確認できます。パスを複数形にするか、ページを何件ずつ返すかといった設計者が決める項目には、選ぶ理由を添えています。修理依頼のサンプルが使う仕様は [OpenAPI 定義](docs/openapi.json) で読めます。

## サンプルコード

| 場所 | 内容 |
| --- | --- |
| [package/app](package/app) | FastAPI のルート、入力と応答の型、OpenAPI の出力 |
| [package/db](package/db) | Alembic によるテーブル定義とマイグレーション |
| [package/infra](package/infra) | API Gateway・Lambda・Aurora をつなぐ Python CDK |
| [tests](tests) | HTTP の契約と DB の権限を確かめるテスト |

Python の依存関係は [pyproject.toml](pyproject.toml) にまとめ、[uv.lock](uv.lock) でバージョンを固定しています。サンプルを手元で起動するコマンドは[第8章](docs/08-fastapi.md)にあります。
