# 実例編 08　件名の項目名を変えたい

[教科書 08　互換性の判断](../textbook/08-compatibility.md) ｜ [設計シート C3　公開済みの契約を変える](../templates/contract-sheet.md#review)

## 要望と決めること

旧画面は登録時に `title` を送り、照会時にも `title` を読みます。画面の表示を「概要」にしたいという依頼が届いたら、まず、表示だけを変えれば仕事が済むかを確認します。

## 選択肢と選んだ理由

| 本当に必要な変更 | 旧画面への影響 | 選ぶ方法 |
| --- | --- | --- |
| 社内画面の見出しを変えたい | 送る値も受け取る値も同じ | 画面の文言を直す。API の仕様はそのまま |
| 一覧を場所で絞れるようにしたい | 条件を省略したときに、一覧の対象・順序・件数が同じなら、今の使い方が続く | 任意のクエリを加え、旧画面の入力例でも確かめる |
| 外部との取り決めで `title` を廃止し、`summary` を必須にしたい | 旧画面の登録は失敗する。照会しても件名を表示できない | 旧画面が使う URL を残し、新しい契約へ利用者ごとに移れる入口を用意する |

現行サンプルのパスは `/repair-requests` です。最後の変更を採るなら、たとえば新版を `/v2/repair-requests` に追加し、旧画面の送信先を保ちます。既存のパスに `/v1` を付け直すと、旧画面にも同時に変更を求めることになります。ここで考えた新版は移行の設計例です。

## 条件が変わったら

画面と API を一緒に更新できても、月末だけ動く集計処理が `title` を読み続けていれば、切り替えは完了していません。その担当者と月末の実行結果を確認し、旧版を閉じる日を決めます。二つの版を別々に配信する場合の設定は[並行稼働の手順](../build/version-rollout.md)にあります。

## 設計シートの記入結果

**C3 公開済みの契約を変える**に、旧画面で使っている入力と期待結果を具体的に書きます。この例なら「旧画面の `title` を含む登録が引き続き `201` になり、返った宛先で同じ件名を読める」です。変更後の確認方法、移行する利用者、旧版の終了条件も同じ欄に残します。[設計シートの公開前点検](../templates/contract-sheet.md#review)
