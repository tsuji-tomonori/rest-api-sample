# 実例編 02　受付番号を何に付けるか

[教科書 02　リソースの選び方](../textbook/02-resources.md) ｜ [設計シート A2　リソースと宛先](../templates/contract-sheet.md#scope)

## 要望と決めること

修理を終えた翌月、同じ椅子の脚がまた緩みました。社員は新しく修理を頼みます。総務には、前の修理を完了のまま残し、今回の依頼を未完了として追いたいという要望があります。何を「1件」と数えればよいでしょうか。

## 選択肢と選んだ理由

| 受付番号を付ける対象 | 翌月にもう一度修理を頼むとどうなるか |
| --- | --- |
| 椅子1脚 | 椅子の番号は変わらない。前回と今回の修理を区別するには、それぞれの依頼を別に記録する必要がある |
| 修理依頼1件 | 同じ椅子でも新しい受付番号を発行できる。前の依頼の完了状態はそのまま残る |

今回は**修理依頼1件**に番号を付けます。仮に前の依頼が42番なら、42番の状態は受付直後の `open` から修理後の `completed` に変わります。状態が変わっても番号は42のままです。翌月の新しい依頼には別の番号が付きます。

## 条件が変わったら

「毎年、何度も故障する備品を買い替えたい」という要望が加われば、椅子にも備品番号を付けます。依頼の受付番号はそのまま使い、各依頼に備品番号を記録すれば、椅子1脚分の修理履歴をたどれます。現在の台帳は件名・場所・状態を扱います。

## 設計シートの記入結果

| 決めること | 記入する内容 |
| --- | --- |
| 何を1件とするか | 社員が一度の受付で頼んだ修理を1件とする |
| 何で見分けるか | 受付が発行した番号。場所や状態が変わっても同じ依頼を指す |
| 必要な読み方 | 社員は受付番号で1件を開く。総務は未完了の依頼を一覧で探す |

<details>
<summary>手元で確かめる（任意）　同じ依頼を開く</summary>


[実例 01](01-http.md)で作成した依頼の番号に、次の `NUMBER` を替えます。Windows の PowerShell では `curl.exe` を使います。

```console
curl -i "http://127.0.0.1:8000/repair-requests/NUMBER"
```

`200 OK` とともに、登録時と同じ `id`、件名、場所が返ります。総務が完了にした後も、この宛先で新しい状態を読めます。[実例 03　入力の置き場所](03-inputs.md)

</details>
