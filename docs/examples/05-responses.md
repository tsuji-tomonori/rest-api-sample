# 実例編 05　受付番号をいつ表示するか

[教科書 05　レスポンスの選び方](../textbook/05-responses.md) ｜ [設計シート B6・B7　成功と失敗](../templates/contract-sheet.md#operation)

## 要望と決めること

社員は修理の完了を待たずに、登録画面を閉じます。画面を閉じてよいのは、依頼が台帳に入り、翌日も同じ番号で開けるときです。

## 選択肢と選んだ理由

登録を受け付けた時点で返す案と、保存を終えてから返す案を比べました。サンプルは1回の呼び出しで保存できるので、保存後に `201 Created` を返します。本文には受付番号と状態、`Location` ヘッダーには次に開く宛先を入れます。

| 台帳で起きたこと | 画面が受け取るもの | 次にできること |
| --- | --- | --- |
| 1件登録した | `201`、登録結果、たとえば `Location: /repair-requests/42` | 受付番号を表示し、その宛先から依頼を開く |
| 1件を開いた、または状態を変えた | `200` と現在の依頼 | 件名、場所、状態を表示する |
| 未完了の依頼を探したが0件だった | `200` と `{"items":[],"next_after":null}` | 「未完了の依頼はありません」と表示する |
| 指定した番号の依頼がなかった | `404` とエラーの説明 | 番号を確かめるか、一覧に戻る |
| 誤登録を取り除いた | `204`、本文は空 | 一覧を更新する |

登録に失敗した画面には、次に直せることを知らせます。この API は JSON の構文が壊れていたら `400`、CSV など受け付けない形式なら `415`、JSON として読めても件名が空白だけなら `422` を返します。アプリが返すエラー本文の形式は `application/problem+json` にそろえています。[公開仕様書](../openapi.yaml)

## 条件が変わったら

もし別のシステムが後で依頼を審査し、その結果が出るまで登録を確定できないなら、最初に `202 Accepted` と進捗を読む宛先を返す案があります。その時点で画面に出せるのは「受付済み」です。登録完了を知らせる時点は、審査結果と一緒に決めます。

## 設計シートの記入結果

**B6 成功時**には「保存後に `201` と取得先を返す」、**B7 失敗時**には「空白だけの件名は `422`。件名を直して再入力する」と書きます。**B9 完成を確かめる例**は「返った宛先に `GET` し、送った件名と場所が読める」です。[設計シートの操作欄](../templates/contract-sheet.md#operation)

<details>
<summary>手元で確かめる（任意）　エラーのステータスと本文を読む</summary>


[手元で API を起動](../build/fastapi.md)してから、一覧の上限に `0` を指定します。Windows PowerShell では `curl` を `curl.exe` に置き換えてください。

```console
curl -i "http://127.0.0.1:8000/repair-requests?limit=0"
```

先頭行の `422` と、ヘッダーの `Content-Type: application/problem+json` を確かめます。`limit=1` に変えると `200` と一覧が返ります。台帳が空でもこの違いを観察できます。

</details>
