# 第6章　操作の契約

設計シートの対応欄　[B4 入力の条件・B5 権限・B8 再送・B9 完成条件](../templates/contract-sheet.md#operation)

## 定義

操作の契約とは、**誰が、どの条件で呼び出すと、何が返り、データがどうなるか**という取り決めです。設計シートの操作欄に、これまでに選んだメソッド・パス・レスポンスを並べ、権限、失敗後の状態、再送、完成を確かめる例を加えます。

## 選択肢

| 決めること | 判断に使う問い | シートに残すもの |
| --- | --- | --- |
| 入力の条件 | 何が必須か。省略、空、上限ちょうど、上限を超えた値をどう扱うか | 許す値の範囲、初期値、拒む条件 |
| 操作できる範囲 | 誰が、どの対象を、どの状態のときに扱えるか | 呼び出し元の確認方法と、対象ごとの許可条件 |
| 変更のまとまり | 一部だけ成功しても、データに意味があるか | 一緒に確定する変更と、失敗後に残る状態 |
| 結果が届かないとき | 同じ操作を送り直してよいか。済んだかどうかを何で調べるか | 重複を許すか、同じ操作を識別する方法、照会先 |
| 完成条件 | 呼び出した側から成功と失敗を見分けられるか | 事前状態、送る値、期待するレスポンス、操作後に読める内容 |

## 選ぶ基準

**権限と入力を別々に確かめます。** 認証は「誰が呼んだか」、認可は「その人がこの対象を操作してよいか」の確認です。番号の形式が正しくても、他人のデータを変更できるとは限りません。一覧も同じ条件で絞り、見せてよい集合を決めてからページに分けます。

**途中の状態を利用者に見せてよいかを決めます。** 一緒に成立すべき変更は、すべて確定するか、すべて取り消すかを約束します。ひとつのデータベースの中なら、トランザクションがこのまとまりを保証します。長い処理の途中経過を公開するなら、受付番号と状態の照会先を用意し、失敗時にどこから再開できるかを定めます。

**再送とやり直しを分けて考えます。** すべての変更を一度に保存しても、その直後に通信が切れれば、利用者には結果が届きません。再送で重複すると困る操作では、同じ依頼を識別するキーと結果を保存し、同じキーの再送には前回の結果を返す方法があります。キーの有効期間と、同じキーで異なる内容が届いた場合の扱いも契約に含めます。

## よくある誤り

「正常な入力なら成功」で終えると、処理済みかを後から確かめられません。成功例には次に取得できる内容を、失敗例には変わらずに残る内容を書きます。たとえば「許可のない相手から更新を受けたら、拒否を返し、元の値を保つ」まで書けば、権限の判定と保存結果の両方を確認できます。

<details>
<summary>発展　同時に届く変更</summary>

二人が同じ空き枠を選ぶなど、読み取りから保存までの間に状態が変わることがあります。重複が禁止なら、その制約を保存時にも保証し、一方が成功した後にもう一方が受け取る結果を決めます。`PATCH` でひとまとまりの変更を依頼する場合は、その変更すべてを原子的に適用するのが仕様です。
