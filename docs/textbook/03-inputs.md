# 第3章　パスと入力の置き場所

設計シートの B3「入力の置き場所」を埋めます。同じ値でも、その値を変えたときに**対象が替わるか、探し方が替わるか、保存する内容が替わるか**で置き場所が決まります。

## 定義

対象を識別するための記述を **URI** と呼びます。この教材で使う **URL** は、アクセス方法と場所を示す URI です。たとえば `https://example.com/books?limit=10` では、`https` が通信方式、`example.com` がホスト名、`/books` がパス、`limit=10` がクエリです。

仕様書の `/books/{book_id}` は、パスのうち実際の値を入れる場所を波かっこで示しています。この値を**パスパラメータ**と呼びます。呼ぶときは `/books/42` のように番号を入れます。

## 入力の置き場所

| 問い | 置き場所 | 書き方の例 |
| --- | --- | --- |
| どの1件か。別の値なら別の対象か | **パス**。個別の対象や所属先を特定する値 | `/books/42` |
| 同じ一覧のうち何を、どの順で、何件読むか | **クエリ**。URL の `?` の後に書く条件 | `/books?category=history&limit=10` |
| 何を保存し、どの値に変えるか | **リクエスト本文**。登録・変更する項目 | `{"title":"資料集"}` |
| 呼び出し元や本文の扱いについて、何を伝えるか | **ヘッダー**。資格情報、本文の形式、処理の前提など | `Authorization: Bearer …`、`Content-Type: application/json` |

## 選ぶ基準

- **番号を誰が決めるか。** サーバーが新しい ID を発行するなら、集合へ登録を頼み、本文には利用者が決める値を入れます。親に属する子を作るなら、すでに決まっている親の ID はパスに置けます。利用者が作成先の ID を決める方式は、第4章の `PUT` が選択肢です。
- **一覧を同じ条件で読み続けられるか。** 絞り込み・並べ替え・件数の既定値と上限を決めます。複数ページに分けるなら、結果の順序を固定し、同じ値が並ぶ場合の順序、続きの取得方法、最終ページの見分け方も決めます。
- **値を省くと何が起きるか。** 入力ごとに型、必須か任意か、範囲を定めます。省略・空文字・`null`（値がないこと）が別の意味を持つ場合は、それぞれの扱いを仕様書に書きます。
- **日付か、ある瞬間か。** 営業日なら `2026-11-19` のように日付を渡します。開始時刻なら `2026-11-19T09:00:00+09:00` のように時差を含めます。「今日の分」を検索できるなら、どの地域の午前0時で区切るかも決めます。

## よくある誤り

パスワードや秘密のトークンをパスやクエリに入れると、URL を共有した相手や、閲覧履歴・アクセスログを読める人に見えるおそれがあります。パスワードを送る方式なら HTTPS のリクエスト本文、発行済みの Bearer トークンなら `Authorization` ヘッダーを使います。本文やヘッダーも取得・記録できるため、認証情報をログから除く設定が必要です。

同じ ID をパスと本文の両方に要求すると、値が食い違ったときに対象が曖昧になります。対象をパスで一度だけ指定できるなら、本文は変更内容に絞ります。

<details>
<summary>発展　検索条件が長いとき、複数あるとき</summary>

短い検索条件はクエリに置くと、その URL で同じ条件を開き直せます。長い条件や機微な情報を含む検索には、本文を受け取る検索操作を設ける方法もあります。HTTP が勧める URI の長さの相互運用目安と、利用するサーバー・中継機器が受け付ける上限は別々に確かめます。

同じ名前で複数値を渡すなら、`?tag=a&tag=b` のように表記を一つ決めます。OpenAPI ではパラメータの `style` と `explode` で、配列を URL に展開する方法を指定できます。
